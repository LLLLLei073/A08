# 数智党校学习系统 · 微信小程序迁移任务清单

> 本文档**不修改任何原有代码**，仅作为迁移规划。所有小程序代码将放在独立的 `packages/miniprogram/`（或独立的仓库/文件夹），与现有 `server` / `admin` / `mobile` / `shared` 解耦。

---

## 一、项目现状速览（用于迁移评估）

| 维度 | 现状 | 对小程序的影响 |
|------|------|----------------|
| 后端 | NestJS + Prisma + MySQL，12 个模块 API，前缀 `/api` | ✅ 可复用，仅暴露给小程序的接口需走 HTTPS 白名单域名 |
| 移动端 | Vue3 + Vite + Vant 的 H5（非小程序） | ❌ 必须重写，H5 无法直接跑在小程序里 |
| 登录 | 用户名 + 密码（`/auth/login`） | ⚠️ 小程序最佳实践是用微信登录；也可先复用账号登录零改造后端 |
| 部署 | `http://120.26.229.95:3000`（HTTP + IP + 端口） | ❌ 小程序**不允许** IP / 端口 / HTTP，必须 HTTPS 标准域名 |
| 前端 API | `axios` 封装，响应 `{code,data,message}` | 🔁 需换成 `wx.request` 封装，逻辑可平移 |
| 富文本 | `md-editor-v3` 渲染 Markdown | 🔁 小程序需换成 `rich-text` 组件或 `towxml` 等方案 |

**移动端功能 → 后端接口映射（小程序要实现的页面）：**

| 移动端页面 | 调用的接口 | 后端模块 |
|-----------|-----------|---------|
| 登录 | `/auth/login`、`/auth/me`、`/auth/change-password` | auth |
| 首页（学习） | `/ai/recommend` | ai |
| 内容学习 | `/contents/visible`、`/contents/:id`、`/contents/categories`、`/contents/:id/record` | content |
| 任务 | `/tasks/my` | task |
| 测验 | `/quizzes/my`、`/quizzes/:id/start`、`/quizzes/:id/submit`、`/quizzes/:id/result` | quiz |
| AI 报告 / 历史 | `/ai/report`、`/ai/report/history` | ai |
| 我的 | `/auth/me`、`/auth/change-password` | auth |

> ⚠️ **不要**在小程序里接入 `question` / `paper` / `settings` / `statistics` 等仅管理员/书记使用的接口（按 CODE_REVIEW 的 P0-3，答案接口本就不应对普通党员开放）。小程序只用上表「党员端」接口即可。

## 二、关键决策（请先确认，决定后续工作量和架构）

### 决策 1：开发方式

| 方案 | 说明 | 推荐度 |
|------|------|--------|
| **原生小程序**（WXML/WXSS/JS） | 独立文件夹，性能最优、可控性最强、无构建耦合 | ⭐⭐⭐⭐⭐ 推荐 |
| **Taro**（React/Vue 语法，写一次多端） | 若未来要同时上支付宝/抖音小程序更划算 | ⭐⭐⭐ |
| **uni-app**（Vue 语法） | 团队已会 Vue，迁移 H5 逻辑更顺手 | ⭐⭐⭐ |

> 推荐**原生小程序**：零构建依赖、包体最小、最贴合微信生态，且完全不碰原 monorepo。下文任务均按原生方案拆解。

### 决策 2：登录方案

| 方案 | 后端改动 | 说明 |
|------|---------|------|
| **A. 先复用账号登录** | 无（直接用 `/auth/login`） | 小程序里做「账号登录」表单，零后端改造，最快上线 |
| **B. 微信一键登录** | 需**新增** `/auth/wechat-login` 接口（不改动现有逻辑） | `wx.login()` 拿 code → 后端换 openid → 绑定/创建党员账号 |

> 推荐：**A 先上线，B 后补**。A 完全不碰原代码即可跑通；B 是体验加分项，作为新增接口实现（additive，不修改既有文件）。

### 决策 3：后端暴露方式（硬性前置）

小程序**强制要求**：所有 `wx.request` 的域名必须：
1. 是 **HTTPS**（标准 443 端口，不能用 IP、不能用非标端口）
2. 在「微信公众平台 → 开发 → 开发管理 → 服务器域名 → request 合法域名」中**提前备案加入白名单**
3. 域名需完成 **ICP 备案**

→ 现有 `http://120.26.229.95:3000` **不可用**，必须准备一个已备案域名 + SSL 证书（可用 Nginx/Caddy 反代到现有 3000 服务）。

### 决策 4：账号体系归属

小程序是要做「党员学习端」还是「含管理端」？建议**只做党员学习端**（对应 `mobile` 包功能），管理/书记功能继续留在后台 Web。本清单据此规划。

## 三、阶段一：基础设施与后端前置（必须先做）

- [ ] **1. 准备已备案域名 + SSL 证书**
  - 例如 `mp.xxx.edu.cn`，Nginx/Caddy 反代到 `127.0.0.1:3000`
  - 验证 `https://mp.xxx.edu.cn/api/health` 可访问且返回 200
- [ ] **2. 微信公众平台配置服务器域名白名单**
  - request 合法域名：`https://mp.xxx.edu.cn`
  - uploadFile / downloadFile 合法域名（如用上传头像）：按需加
  - socket 合法域名：本项目暂不需要
- [ ] **3.（可选，决策 2-B）新增微信登录接口**
  - 新建文件，不修改现有 `auth` 模块逻辑：`POST /auth/wechat-login`
  - 用 `code2Session` 换 `openid`/`unionid`，与党员账号绑定（首次登录按 unionid 匹配或引导绑定账号）
- [ ] **4. 确认给小程序用的接口响应结构**
  - 现有响应是 `{code, data, message}`，小程序 request 层直接复用该约定即可，无需后端改动
- [ ] **5. 隐私合规前置**
  - 在微信后台「设置 → 服务内容 / 用户隐私指引」填写隐私政策
  - 后端如需读取 userInfo 等敏感信息，要配合小程序 `wx.requirePrivacyAuthorize` 流程

## 四、阶段二：小程序工程搭建（独立文件夹，不碰原代码）

- [ ] **6. 创建独立工程目录**（建议 `packages/miniprogram/`，或独立 git 仓库）
  - 用「微信开发者工具」新建**小程序**项目（不是「小程序·云开发」除非要用云开发）
- [ ] **7. 全局配置 `app.json`**
  - `pages`：登录、首页、内容详情、任务、测验列表、答题、结果、报告、历史、我的
  - `tabBar`：首页 / 任务 / 测验 / 我的（4 个底部 tab）
  - `window`：导航栏标题、背景色（党校风格：红 `#C8161D` 主色）
  - `subpackages`：把「报告/历史/内容详情」等非首屏放进分包
- [ ] **8. 网络层 `utils/request.js`**（平移 mobile 的 `api/http.ts` 逻辑）
  - 封装 `wx.request` 为 Promise
  - 请求头带 `Authorization: Bearer <token>`（token 存 `wx.storage`）
  - 统一处理 `{code,data,message}`，`code!==0` 走 `wx.showToast`
  - 401 时跳登录页（小程序用 `wx.reLaunch`）
- [ ] **9. 登录态管理 `utils/auth.js`**
  - `wx.login()` / 账号登录 → 存 token 到 `wx.setStorageSync`
  - 提供 `getToken()` / `isLogin()` / `logout()`
- [ ] **10. 全局样式 `app.wxss`**
  - 定义主题色变量、通用卡片/按钮/空状态样式，统一党校视觉
- [ ] **11. 分包规划（控制主包 ≤ 1.5MB）**
  - 主包：登录、首页、任务、测验列表、我的（tabBar 必须主包）
  - 分包 `subpkg-study`：内容详情、答题、结果
  - 分包 `subpkg-report`：AI 报告、历史

## 五、阶段三：页面开发（对齐移动端 9 类功能）

> 每页对应 mobile 的 `.vue`，逻辑平移，UI 改写为 WXML/WXSS。

- [ ] **12. 登录页 `pages/login`**
  - 账号登录表单（决策 2-A，零后端改动）
  - （决策 2-B 后）加「微信一键登录」按钮
  - 默认测试账号仅 DEV 环境提示（对应 CODE_REVIEW P0-6）
- [ ] **13. 首页 `pages/index`**（tab）
  - 顶部欢迎 + 学习进度概览
  - 调用 `/ai/recommend` 展示推荐学习内容
  - 快捷入口：继续学习 / 待办任务 / 待考试
- [ ] **14. 内容学习页 `subpkg-study/content`**
  - 列表：`/contents/visible` + 分类筛选 `/contents/categories`
  - 详情：`/contents/:id`，Markdown 正文用 `rich-text` 渲染（需把 Markdown 转 HTML，建议后端返回已渲染 HTML 或前端用 `towxml`）
  - 学习记录：`/contents/:id/record`（进入/离开时上报进度）
- [ ] **15. 任务页 `pages/task`**（tab）
  - `/tasks/my` 列表，展示支部下发的学习任务与完成状态
- [ ] **16. 测验页 `pages/quiz`**（tab）
  - 列表 `/quizzes/my`，区分「未开始/进行中/已完成」
  - 答题页 `subpkg-study/quiz-take`：`start` → 逐题作答 → `submit`
  - 结果页 `subpkg-study/quiz-result`：`/quizzes/:id/result`
  - ⚠️ 小程序内**不要**回显答案（沿用后端已做的安全策略）
- [ ] **17. AI 报告页 `subpkg-report/report`**
  - `/ai/report` 学习报告展示
  - 历史 `/ai/report/history`
- [ ] **18. 我的页 `pages/profile`**（tab）
  - `/auth/me` 展示党员信息、支部
  - 修改密码 `/auth/change-password`
  - 退出登录
- [ ] **19. 社交分享能力**
  - 内容/报告页实现 `onShareAppMessage`（分享给好友）
  - 实现 `onShareTimeline`（分享到朋友圈），提升传播

## 六、阶段四：性能优化（微信特有约束）

- [ ] **20. 包体控制**：主包 < 1.5MB，图片走 CDN（WebP），不用本地大图
- [ ] **21. setData 优化**：合并多次 setData 为一次；只传视图需要的字段；避免在 `onPageScroll` 里高频 setData
- [ ] **22. 列表虚拟渲染**：学习任务/测验列表数据多时用 `recycle-view` 或分页加载
- [ ] **23. 图片懒加载**：`image` 组件 `lazy-load`，封面图用 CDN 缩略图参数
- [ ] **24. 启动加速**：非首屏逻辑延迟初始化；分包预下载 `preloadRule` 配置常用分包

## 七、阶段五：合规与提审

- [ ] **25. 隐私弹窗**：首次进入调用 `wx.requirePrivacyAuthorize`，用户同意后再申请 `scope` 权限
- [ ] **26. 内容安全**：用户 UGC（如学习留言，如有）调用 `msgSecCheck` 校验
- [ ] **27. 真机测试**：iOS + Android 各机型、弱网环境跑通全流程
- [ ] **28. 提审材料**：准备小程序名称/类目（教育-党政学习）、简介、截图
- [ ] **29. 规避常见驳回**：
  - 类目选择正确（避免「社交」等需资质的类目）
  - 不强制收集与功能无关的个人信息
  - 登录页有明确隐私政策入口
  - 不涉及虚拟支付（本项目纯学习，无支付，规避支付类驳回）
