# 数智党校系统生产化加固设计

**日期：** 2026-08-13  
**状态：** 已确认，进入实施

## 目标

在不改变现有产品主流程的前提下，修复审查中发现的鉴权、组织数据隔离、考试可信度、学习数据可信度与部署可复现性问题，并为后续功能完善建立可验证的工程基线。

## 设计原则

1. 浏览器只通过 HttpOnly Cookie 持有令牌，业务响应不返回访问令牌或刷新令牌。
2. 数据库中的用户状态是会话有效性的最终依据；Redis 只能作为缓存，不能成为唯一的失效机制。
3. 支部书记只能读取、生成、发布和删除本支部数据，管理员保留全局视角。
4. 考试开始时间必须由服务端持久化，提交时同时校验考试窗口和个人答题时限。
5. 学习时长按服务端可观察到的时间增量累计，客户端上报值只作为候选值。
6. 生产环境必须显式配置跨域来源、数据库迁移和初始账户密码；缺失配置时安全失败。

## 关键方案

### 鉴权与会话

- `User` 增加持久化的 `securityVersion`。
- JWT 守卫每次请求加载当前用户，校验用户存在且令牌版本一致，并用数据库中的角色、组织覆盖令牌快照。
- 修改密码、重置密码、角色或组织后递增版本，使旧访问令牌和刷新令牌立即失效。
- 强制改密用户只能访问当前用户信息、退出和设置新密码接口；普通用户不能调用免旧密码的设置密码接口。
- 登录接口写入 Cookie 后只返回用户信息与强制改密标志。

### 组织数据边界

- 统计总览按调用者组织范围计算，并取消跨用户共享的总览 HTTP 缓存。
- AI 自然语言查询只向支部书记暴露本支部工具数据。
- AI 报告的列表、详情、生成、发布和删除统一执行组织归属校验。

### 考试与学习可信度

- 开始考试时创建未提交的 `QuizRecord`，重复开始返回同一场答题的剩余时间。
- 提交时更新既有答题记录，拒绝超出考试结束时间、个人时长或重复提交的请求。
- 学习记录根据数据库更新时间限制每次可接受的时长增量，并用可信时长约束完成状态。
- 新增按日累计表，统计趋势不再依赖一条累计学习记录的最后更新时间。

### 输入、运行与部署边界

- 为更新请求和分页/筛选查询补齐运行时 DTO 校验。
- 压缩文件解析同时限制压缩前、解压后单项和累计大小。
- 生产环境没有 CORS 白名单时禁止跨域；依赖异常时健康检查返回 503。
- 提交正式 Prisma 迁移，部署脚本使用 `migrate deploy`，不再覆盖 schema 或执行 `db push`。
- 建立可运行的 ESLint 配置、测试覆盖和完整 README。

## 兼容与迁移

- 旧 JWT 没有 `securityVersion`，升级后会要求重新登录。
- 已存在的夸大学习时长不会自动回滚；新请求开始受服务端增量限制，历史数据应另行审计。
- 既有数据库部署正式迁移前需按 Prisma 基线流程标记初始迁移；全新环境可直接执行迁移。
